# TrafficControl

**Python · asyncio · RabbitMQ · FastAPI · Canvas API · Docker Compose**

Учебная многоагентная система управления четырьмя перекрёстками. Десять агентов на Python обмениваются адресными сообщениями через RabbitMQ. В браузере видны светофоры, очереди автомобилей, движение скорой и журнал сообщений.

[Отчёт о проекте](docs/TrafficControl-Report-4.docx) · [Журналы пяти прогонов](docs/logs)

## Запуск через Docker Compose

Установите Docker Desktop (Windows или macOS) либо Docker Engine с плагином Compose (Linux). Откройте Docker Desktop, если он установлен. Скачайте репозиторий через **Code → Download ZIP** или выполните команды Git:

```sh
git clone https://github.com/polimag/traffic-control.git
cd traffic-control
```

Из каталога `TrafficControl` выполните:

```sh
docker compose up --build -d
docker compose ps
```

Дождитесь, пока RabbitMQ получит статус `healthy`, а приложение — `Up`. Откройте <http://localhost:8000>. При первом запуске Docker скачивает образы и устанавливает Python-зависимости.

Выберите сценарий и нажмите **Запустить**. Скорость **4×** подходит для просмотра движения, **1×** — для подробного наблюдения за машинами и сигналами, **12×** и **30×** — для быстрого прогона. Нажмите **Скачать лог**, чтобы сохранить полный журнал текущего прогона. Запуск следующего сценария начинает новый журнал. Кнопка **Остановить** завершает текущий прогон и оставляет его журнал доступным.

| Сценарий | Что искать на карте и в журнале |
| --- | --- |
| UC-01 · Адаптация фаз | На П1 пустая фаза заканчивается через 15 с. Следующий зелёный продлевается по 5 с до 60 с. |
| UC-02 · Зелёная волна | П1 и П2 подтверждают общий план. Зелёный вдоль улицы включается на 140-й и 162-й секундах модельного времени. |
| UC-03 · Разгрузка затора | Координатор снимает зелёную волну и назначает вдоль улицы 15 с на П1 и 45 с на П2. Когда заполнение западного подхода П2 падает ниже 50%, план отменяется. |
| UC-04 · Отказ датчика | Датчик П3 отказывает, светофор переходит на резервный план и возвращается в адаптивный режим после восстановления. |
| UC-05 · Проезд скорой | Белая машина с красным крестом движется через П1 и П2. Зелёный подтверждается на 35-й и 71-й секундах, проезд фиксируется на 36-й и 72-й. |

### Автоматическая проверка

При запущенном Compose:

```sh
docker compose exec app python verify.py
```

Команда прогоняет пять сценариев через реальный RabbitMQ. Она проверяет ожидаемые сообщения, переключения и их интервалы, а также проход одной и той же машины через два перекрёстка по горизонтали и вертикали с остановкой на запрещающий сигнал. Успешный запуск выводит пять строк `OK`. Можно сохранить свои журналы при запуске проверки из установленного локально Python:

```sh
python verify.py --logs logs-check
```

Если порт 8000 занят, создайте рядом с compose.yaml файл .env со строкой `TRAFFIC_PORT=8080`, повторите запуск и откройте <http://localhost:8080>.

Посмотреть состояние и сообщения контейнеров:

```sh
docker compose ps
docker compose logs --tail=60 app rabbitmq
```

Остановить программу и RabbitMQ:

```sh
docker compose down
```

## Запуск без Compose

Понадобятся Python 3.12 и RabbitMQ. Брокер можно запустить одним контейнером:

```sh
docker run -d --name traffic-rabbit -p 127.0.0.1:5672:5672 -e RABBITMQ_DEFAULT_USER=traffic -e RABBITMQ_DEFAULT_PASS=traffic-demo rabbitmq:4.1-alpine
```

Из каталога `TrafficControl` создайте виртуальное окружение и используйте его интерпретатор. В Linux и macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

В Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

Если RabbitMQ установлен отдельно с другими параметрами, задайте переменную окружения `AMQP_URL` с его адресом и учётными данными. Консольный сервер останавливается сочетанием **Ctrl+C**, демонстрационный контейнер — командой `docker stop traffic-rabbit`. Повторный запуск контейнера — `docker start traffic-rabbit`.

## Устройство программы

- `agents.py` — датчики, светофоры, координатор и агент экстренных служб.
- `transport.py` — адресная доставка JSON-сообщений через AMQP и журнал.
- `traffic.py` — движение машин по связанным дорогам, очереди и показания датчиков.
- `simulation.py` — виртуальное время и запуск пяти сценариев.
- `server.py`, `static/` — локальный HTTP-интерфейс и карта.
- `verify.py` — проверка сценариев и фаз по журналу.

Обычные машины движутся прямо по своей полосе через два перекрёстка, сохраняя положение и цвет на всём маршруте. При красном или жёлтом они ждут у стоп-линии. На карте у каждого перекрёстка четыре индикатора с буквами С, Ю, З и В. Число рядом с буквой показывает длину очереди на этом подходе, если она есть. Реальные потоки заменены заданными для сценариев учебными параметрами.
